# Распределённые вычисления интеграла

Данный репозиторий содержит три проекта, демонстрирующих различные подходы к организации вычислений: от многопоточной оптимизации загрузки процессора до построения отказоустойчивого кластера серверов. Во всех проектах решается одна и та же математическая задача – вычисление определённого интеграла функции f(x) = cos(x²) на отрезке [1, 2] методом трапеций с шагом 1e-7.

## ParallelIntegralWithCPULoadControl: Многопоточный вычислитель с контролем загрузки CPU

**Назначение**: демонстрация управления загрузкой процессора в многопоточной среде с помощью чередования вычислений и принудительного сна.

**Особенности**:
- Создаёт по одному потоку на логическое ядро.
- Каждый поток обрабатывает блоки (`CHUNK_SIZE`) общей задачи.
- Разбивает интервал интегрирования на крупные блоки (CHUNK_SIZE), которые потоки забирают атомарно.
- В каждом потоке измеряется реально затраченное процессорное время (через GetThreadTimes).
- Поток может входить в состояние сна, чтобы искусственно снизить нагрузку до заданного процента.
- Выводится статистика: итоговое значение интеграла, общее время работы, общее время работы, суммарное время сна, достигнутый процент загрузки.

**Запуск**:

ParallelIntegralWithCPULoadControl.exe [нагрузка_процентов]

Нагрузка — целое число от 0 до 100 (по умолчанию 100). При запуске без параметра программа запросит значение интерактивно.

## DistributedTaskQueue: Клиент-серверное распределённое вычисление

### Компоненты

- Сервер – принимает заданное количество клиентов, разбивает интеграл на равные части и раздаёт их клиентам. Собирает результаты и выводит итоговую сумму.

- Клиент – подключается к серверу, получает подзадачу (начальная точка x0, количество шагов nsteps), вычисляет интеграл на своём интервале и отправляет результат обратно.

### Сервер

**Назначение**: раздаёт фрагменты интеграла подключившимся клиентам и собирает результаты.

**Особенности**:
- Ожидает заданное количество клиентов.
- Разбивает общий интервал на равные части (по количеству клиентов) и выдает каждой клиенту задание в виде сообщения `TASK x0 dx nsteps`.
- Клиенты возвращают результат строкой `RESULT значение`.
- Сервер суммирует результаты и выводит итоговое значение.
- Используется неблокирующий ввод-вывод (`select`) для обработки нескольких клиентов.
- Контролируется общий таймаут выполнения (5 минут).
- При потере клиента его задание возвращается в очередь.

**Запуск сервера**:

Server.exe <порт> <количество_клиентов>

Если параметры не указаны, запрашиваются интерактивно.

### Клиент

**Назначение**: подключается к серверу, получает задание, вычисляет свой фрагмент интеграла, отправляет результат.

**Особенности**:
- Получает от сервера строку `TASK x0 dx nsteps`.
- Отправляет результат строкой `RESULT значение`.
- При разрыве соединения пытается переподключиться к тому же серверу.

**Запуск клиента**:

Client.exe <IP_сервера> <порт>

Если параметры не указаны, запрашиваются интерактивно.

## FaultTolerantLeaderBasedCluster: Кластер серверов с репликацией и лидерством

**Назначение**: построение распределённой системы, способной переживать отказы отдельных узлов. Один из серверов выбирается лидером и распределяет задачи; остальные перенаправляют клиентов к лидеру, реплицируют состояние (назначенные задачи и результаты) и могут взять на себя роль лидера при отказе текущего.

### Сервер

- Общается с другими серверами через отдельный порт.
- Постоянно выполняет выбор лидера: лидером считается узел с наименьшим идентификатором
- Если узел является лидером:
- - Принимает клиентов на client-порт.
- - Раздаёт задачи (нарезает интеграл блоками по CHUNK_SIZE).
- - Отслеживает таймауты выполнения задач (300 секунд на задачу).
- - Реплицирует назначения задач другим серверам (ASSIGN).
- - Получает результаты от клиентов и рассылает их другим серверам (RESULT).
- Если узел не лидер:
- - Перенаправляет входящих клиентов на лидера командой REDIRECT.
- - Принимает от лидера реплицированные назначения и результаты (чтобы иметь актуальное состояние при смене лидера).

### Клиент
- Принимает список адресов серверов
- Последовательно пытается подключиться к одному из них.
- Получив команду REDIRECT, подключается к указанному новому серверу.
- Получает задачу (TASK), вычисляет интеграл, используя все доступные ядра
- Отправляет результат (RESULT).
- При разрыве соединения пытается переподключиться к любому известному серверу.

**Запуск сервера пула**:

Server.exe <client_port> <num_clients> <server_port> [server1_ip:server_port ...]

- `client_port` - порт для приёма клиентов.
- `num_clients` - максимальное количество клиентов.
- `server_port` - порт для межсерверного общения.
- Далее перечисляются адреса других известных серверов в формате `ip:server_port` (необязательно).

**Запуск клиента**:

Client.exe <addr1:port1> [addr2:port2 ...]
